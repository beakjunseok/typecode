# TYPE//CODE

코드 문법 토큰(`const`, `=>`, `fmt.Println()`, `GROUP BY` …)을 치는 개발자용 타자연습 게임.
**연습** 모드와, 한컴타자연습의 추억의 게임을 패러디한 아케이드 모드 2종(**📱 휴대폰 던지기**, **🔋 배터리 구조 SOS**)이 있다.
토큰은 종류(keyword · type · builtin · operator · literal · decorator · directive)별로 에디터처럼 색이 입혀지고,
오타는 에러 로그로 남는다. 주간 랭킹은 서버에 저장된다.

**플레이:** https://typecode-coral.vercel.app

## 규칙
- 언어 12종(JavaScript · TypeScript · Python · Java · C · C++ · C# · Go · Rust · Kotlin · Swift · SQL), 시간 30 · 60 · 120초. 첫 키 입력부터 타이머 시작
- 출제 비율은 종류 단위로 고정(keyword 34% · builtin 22% · type 14% · operator 12% · 나머지). 토큰 수가 많은 언어에서도 한 종류만 쏟아지지 않음
- 토큰을 끝까지 맞게 채우면 자동으로 다음 토큰. 틀린 글자는 빨갛게 남고 `Backspace`로 지우면 원래 색으로 돌아온다
  (`Ctrl/Alt + Backspace`: 토큰 전체 삭제)
- 점수 = 토큰 글자 수 × 10 × 배율, **토큰 완성 시 한 번만** 지급(지웠다 다시 쳐서 점수를 불릴 수 없음)
- 오타 없이 끝낸 토큰이 이어지면 콤보: 10개 이상 ×1.5, 30개 이상 ×2.0. 한 번 틀린 토큰은 고쳐도 콤보 0
- 틀린 토큰은 20% 확률로 다시 출제. 결과 화면에 타수 추이(5초 이동 평균)와 자주 틀린 토큰 TOP 3
- **Enter = 건너뛰기**: 지금 토큰을 틀린 것으로 기록하고 다음 토큰으로(콤보 끊김 · 틀린 타 +1 · 점수·시간 보너스 없음 · 자주 틀린 토큰으로 다시 출제될 수 있음). 결과 화면에 건너뛴 수 표시
- 속도는 **타수**(분당 타자 수, 한컴타자연습 기준)로 표시하고 WPM(= 타수 ÷ 5)을 함께 보여준다. 랭킹에도 타수

### ⏳ 시간 연장 (연습 모드의 세부 방식)
`30s · 60s · 120s · ⏳연장` 중 `⏳연장`을 고르면 **20초로 시작해 토큰을 맞출 때마다 시간이 늘어난다.** 랭킹은 `연습 · 시간 연장`으로 따로 집계.

| 규칙 | 값 |
|---|---|
| 토큰 하나당 추가 시간 | 0.25초 + 글자당 0.12초 (`return` → 0.97초) |
| 오타가 있었던 토큰 | 40%만 |
| 콤보 단계(×1 · ×1.5 · ×2.0) | 시간 보너스 ×1 · ×1.15 · ×1.3 |
| 남은 시간 상한 | 30초 (타이머 막대 100%) |
| 보너스 감쇠 | 0~4분: 100% → 15%, 4~8분: 15% → 0% → 최대 510초면 반드시 끝남 |

시뮬레이션(JavaScript 토큰, 오타 3%): 분당 120타 ≈ 27초 · 300타 ≈ 55초 · 550타 ≈ 3분 · 800타 ≈ 3분 40초.
점수 규칙은 고정 시간 연습과 같다. 서버는 생존 시간이 `20초 + 정타 × 글자당 최대 보너스(0.481초)`와 510초를 넘으면 거부한다(`implausible_time`).

## 아케이드 모드

게임(휴대폰 던지기 · 배터리 구조)에서 **Enter = 친 낱말 지우기**: 입력을 한 번에 비우고 조준을 풀어 다른 목표를 고를 수 있다(콤보·점수 유지).
공통: 첫 글자로 목표를 조준(화면의 목표끼리 첫 글자가 겹치지 않게 출제) → 토큰을 다 맞게 치면 발사. 오타·Backspace 규칙은 연습과 같다.
생명 3, 시간이 갈수록 빨라지고 자주 나온다. 난이도 Lv.1~4. 랭킹은 모드별로 따로 집계.

**📱 휴대폰 던지기** (케이크 던지기 패러디, 세로 화면) — 로봇이 낱말 발판을 타고 위에서 내려온다(가까울수록 커짐).
발판 낱말을 다 치면 아래 책상의 개발자가 휴대폰을 던진다. 빨간 선을 넘으면 건전지 생명 −1칸(왼쪽 위 건전지 3개, 마지막 1칸은 빨갛게 깜빡임). 좁은 화면은 3레인·짧은 낱말.
| 적 | 체력 | 속도 | 보너스 | 등장 |
|---|---|---|---|---|
| 버그봇(기본) | 1 | 보통 | 50 | 처음 |
| 스피드봇(빠른) | 1 | 2배 | 80 | 15초 |
| 헤비봇(피 많은) | 3, 맞을 때마다 새 낱말 | 느림 | 150 | 35초 |

아이템(드론이 운반): 💻 노트북(8초간 위력 ×3, 헤비봇 한 방) · 🔋 건전지(생명이 깎이면 6~10초 뒤, 이후 깎여 있는 동안 14~22초마다 등장 · 생명 +1칸)

**🔋 배터리 구조 SOS** (해상구조 SOS 패러디) — 왼쪽 내 폰 vs 오른쪽 방전봇, 두 배터리 셀 탑이 계속 방전의 바다로 가라앉는다.
지나가는 아이템 낱말을 치면 내 탑 충전, 방전봇 탑 위 낱말을 치면 상대 −0.5칸. 방전봇도 같은 아이템을 노리고(빨간 밑줄 = 진행도) 먼저 치면 뺏긴다.
8칸(100%)을 먼저 채우면 스테이지 클리어 → 탑 초기화, 다음 스테이지는 더 빠름. 0%가 되거나 방전봇이 먼저 채우면 패배.
아이템: 🔋 셀(+0.5) · 보조배터리 드론(+1) · 🍃 저전력(내 방전 4초 감속) · 🔥 발열(상대 4초 급방전) · 🌙 화면 꺼짐(방전봇 3초 정지)

### 👥 배터리 구조 PvP (친구와 1:1)
배터리 구조에서 `🤖 AI | 👥 PvP` 중 PvP → **방 만들기**로 4자리 코드(또는 `?room=코드` 초대 링크)를 친구에게 보내고, 친구는 코드로 **참가**.

- **3판 2선승**: 한 판 = 먼저 100%(8칸) 충전하거나 상대를 0%로 만든 쪽 승리, 판마다 조금씩 빨라짐
- 서로 자기 탑이 왼쪽(손님 화면은 좌우 반전), 상대는 주황색 폰 캐릭터 · 상대가 치는 낱말은 빨간 밑줄로 보임
- 같은 아이템은 먼저 다 친 사람 것 · 🌙 화면 꺼짐은 상대 입력 3초 막기 · 방장의 언어·난이도로 진행
- 경기 뒤 **한 판 더**(손님은 요청), 상대가 나가거나 6초 넘게 상태가 끊기면 '연결 끊김'으로 끝남 · 랭킹에는 안 올라감

**구조**: 두 기기는 **WebRTC 데이터 채널로 직접(P2P)** 연결된다. 서버(`/api/room`)는 연결 정보(SDP offer/answer, ICE 후보 포함)만 Blob에 잠깐(10분) 맡겨 전달한다.
- **방장 판정**: 방장 기기가 경기를 돌리고(`BatteryPvpHostEngine`) 초당 20번 상태를 보낸다. 손님(`BatteryPvpGuestEngine`)은 타자·조준·점수를 자기 기기에서 바로 처리하고, 낱말을 다 치면 '가져가기' 요청 → 방장이 판정(늦으면 거절)
- STUN만 쓰므로 일부 통신사 망(대칭형 NAT)에서는 직접 연결이 안 될 수 있다 → 같은 와이파이나 다른 네트워크로 안내
- 방장 키(해시만 저장)가 있어야 손님 응답을 읽을 수 있고, 손님은 한 명만(두 번째는 409)

모바일: 게임 화면 아래 입력창(`>`)에 지금 치는 낱말과 오타가 보이고, 화면 키보드가 올라와도 게임 높이를 다시 맞춘다.
조합형 입력(Gboard·삼성 키보드)·자동수정·스와이프도 값 비교 방식으로 처리한다.

## 리듬 모드 (🎵)

- **곡 선택**: 다른 리듬 게임처럼 곡 목록에서 곡과 난이도(EASY · NORMAL · HARD · EXPERT)를 고른다. ↑↓ 곡, ←→ 난이도, 곡을 고르면 첫 5초 미리듣기. 레벨 숫자(1~15)는 분당 칠 글자 수로 잰다. 곡·난이도별 최고 점수·랭크는 이 기기에 저장.
- **수록곡 33곡**: 직접 채보한 선율 13곡(신세계 라르고 · 쇼팽 녹턴 · 작은 별 · 고요한 밤 · 스와니 강 · 징글벨 · 아름답고 푸른 도나우 · 아이네 클라이네 나흐트무지크 · 코로부시카 · beat-compiler.wav · 캉캉 · 윌리엄 텔 서곡 · 왕벌의 비행)과 Mutopia Project MIDI에서 가져온 20곡(터키 행진곡 · 엔터테이너 · 메이플 리프 래그 · 엘리트 싱코페이션 · 엘리제를 위하여 · 환희의 송가 · 산왕의 궁전에서 · 비창 2악장 · 달빛 · 브람스 자장가 · 토카타와 푸가 · 바흐 부레·코랄 · 거룩한 밤 · 캐논 등). MIDI 곡은 `node scripts/import-midi.mjs`가 `scripts/midi/`의 원본에서 선율(맨 윗성부)과 반주(나머지 음)를 나눠 `public/js/rhythm-songs-midi.js`로 만들고, 반주는 악보의 음 그대로 합성해 연주한다. 150초가 넘는 곡은 마디 경계에서 자르고, 60초보다 짧은 곡은 반복한다.
- **MIDI 라이선스**: 곡마다 Mutopia 페이지에서 확인한 Public Domain 또는 CC BY 파일만 쓴다(CC BY-SA·비상업·라이선스 미확인 파일은 제외, 테스트가 막는다). 출처 표시가 필요한 곡: 캐논 D장조(Jim Paterson · mfiles.co.uk, Mutopia #1700, CC BY 3.0), 줄리아니 Op.50-24(Mutopia #1352, CC BY 3.0). 곡 선택 화면의 곡 정보에 출처 링크가 있다.
- **악보**: 곡 선율의 음 중 난이도 격자(EASY 1박 · NORMAL/HARD ½박 · EXPERT ¼박)에 있고 앞 노트와 최소 간격(0.8 · 0.5 · 0.32 · 0.2초) 이상 떨어진 음에 코드 낱말의 글자를 하나씩 얹는다. 맞힌 글자는 그 음으로 울리고(키 사운드), 글자를 얹지 않은 음은 자동 연주된다.
- 레인 = 그 글자를 치는 손가락 구역(왼손 바깥 · 왼손 안쪽 · 오른손 안쪽 · 오른손 바깥). 화면 맨 위에 지금 만드는 낱말과 다음 낱말.
- 판정: ±50ms PERFECT · ±100ms GREAT · ±150ms GOOD · 그 밖 BAD · 0.25초 지나면 MISS. 일찍 누른 키는 무시, 범위 안 다른 글자는 오타. 대문자 노트는 소문자로 쳐도 맞다(리듬 모드만).
- HP 100에서 MISS −8 · BAD −3 · 오타 −2, 0이면 실패. 곡 끝까지 버티면 클리어, 판정 정확도로 S~D 랭크.
- 시계: 게임 시간은 `AudioContext.currentTime − outputLatency`의 증가분을 따른다(오디오가 안 돌면 성능 시계). 반주는 프레임마다 0.15초 앞을 `audioOffset + 게임 시각`에 예약한다.
- `rhythm-songs.js`(곡·난이도) · `rhythm-engine.js`(악보·시계·판정) · `rhythm-music.js`(반주·미리듣기) · `rhythm-view.js`(캔버스) · `song-select.js`(곡 선택 화면)

## 화면 키보드

연습 모드에서는 기본으로 보이고, 휴대폰 던지기·배터리 구조에서는 기본으로 숨겨져 있다가 ⌨ 버튼으로 켤 수 있다(두 설정은 따로 기억). 게임에서는 잡고 있는 낱말의 다음 글자(오타가 있으면 Backspace)를 표시하고, 친 키에 LED가 반응한다.

## 키보드 뽑기 · 도감

- **🎁 뽑기**: 하루 한 번(기기 시각 자정 기준) 무료. 키캡 캡슐이 떨어져 흔들리며 빛을 모으고(희귀 이상이면 도중에 빛이 등급 색으로 바뀜), 섬광과 함께 키캡 조각이 터지며 결과가 나온다. 영웅·전설은 화면이 흔들리고 빛줄기가 더 강하다. 효과음은 모으는 소리(등급만큼 높이 올라감)와 등급별 보상음(높을수록 화음·종소리·저음이 쌓임). 화면을 누르거나 '건너뛰기'로 바로 결과.
- **게임 포인트**: 판이 끝날 때마다 적립(맞게 친 글자 10개당 1P × 정확도², 최대 콤보 10마다 2P, 한 판 최대 300P, 맞게 친 글자 20개 미만이면 0P). 결과창에 적립량 표시. 포인트로 1회(100P) 또는 10회(900P, 희귀 이상 1개 이상 보장) 뽑기. 10회는 카드 10장이 차례로 뒤집히고(희귀 이상은 소리), 카드를 누르면 크게 본다.
- **확률**: 일반 55% · 고급 27% · 희귀 12% · 영웅 4.5% · 전설 1.5%. 희귀 이상 10회, 영웅 이상 30회 천장, 전설은 45회째부터 매회 +5%p, 60회째 확정. 천장으로 나온 영웅·전설은 없는 것부터. 첫 뽑기는 희귀 이상. 중복은 키캡 조각(5/10/25/60/150)으로 돌려받고, 도감에서 조각으로 원하는 스킨을 살 수 있다(40/80/200/500/1200).
- **📖 도감**: 50종(일반 18 · 고급 14 · 희귀 9 · 영웅 5 · 전설 4) + 기본 스킨. 등급·보유 필터, 실시간 미리보기(키를 치거나 눌러 LED 반응 확인), 장착, 조각 구매.
- **스킨**: 실제 키캡 세트의 배색만 참고한 오리지널 디자인. 글자키·기능키·포인트키(Enter·Backspace) 3단 배색 + 케이스 + 소재(PBT, 샤인스루, 푸딩, 크리스탈, 프로스트, 세라믹, 월넛·황동, 아노다이징, 블랭크).
- **LED 평상시 무늬 31가지**: 꺼짐, 고정, 두 색, 세로·가로 그라데이션, 숨쉬기, 색 바뀌는 숨쉬기, 심장박동, 스펙트럼 순환, 웨이브(가로·세로·대각선·화살표), 안에서 밖으로, 연못 물결, 바람개비, 소용돌이, 쌍등대, 레이더, 스캐너, 혜성, 빗방울, 별빛, 문자비, 불꽃, 오로라, 플라즈마, 진자, 체크 점멸, 소리 막대·소리 맥박(게임 효과음·BGM 실시간 분석).
- **터치 반응 15가지**: 없음, 누른 키, 잔광, 주변 번짐, 십자, 십자 질주, 물결, 무지개 물결, 충격파, 줄 훑기, 낙하, 불꽃놀이, 블랙홀(빛을 삼킴), 열 지도(자주 친 키가 뜨거워짐), 물감(누를 때마다 색칠).
- 가진 스킨이 쓰는 무늬·반응은 도감의 '내 키보드 LED'에서 장착한 스킨에 섞어 쓸 수 있다. 전설 일부는 콤보에 비례해 빨라지고 밝아진다. 움직임 줄이기 설정이면 LED·연출 애니메이션을 멈춘다.
- 보관함은 이 기기(localStorage)에만 저장된다.

## 키 소리
| 상황 | 소리 | 방식 |
|---|---|---|
| 맞는 키 | 청축(클리키): 높은 '찰칵' + 스프링 '칭' → 바닥 소리 → 올라올 때 '찰칵' | Web Audio 합성 |
| 틀린 키 | 적축(리니어): 누름 → 70~105ms 뒤 올라옴 | **실제 녹음** 12+12개 중 직전과 다른 것, ±18 cents·±2 dB 변화 |
| Backspace | 넓은 키 누름·올라옴 | 실제 녹음 3+3개 |

- 키 위치대로 좌우 배치(q는 왼쪽, p는 오른쪽), 짧은 방 울림. 키 소리는 BGM과 다른 출력(전용 limiter)으로 보내 BGM에 묻히지 않는다.
- 녹음은 `public/sounds/linear.wav` 한 파일(32 kHz stereo, 319 KB)에 묶어 첫 입력 뒤에 한 번 받는다. 받기 전이나 실패 시에는 합성음으로 대신한다.
- 출처: [gabrimatic/switchtone](https://github.com/gabrimatic/switchtone) `Resources/Sounds/linear` (MIT) ← Sony Keyboard Sound Dataset (MIT, Copyright 2020 Sony Corporation). 전문: `public/sounds/LICENSES.txt`.
  다시 만들기: `python3 scripts/build-key-samples.py <switchtone>/Resources/Sounds/linear` (ffmpeg 필요)

## 디자인
밤에 켜 둔 개발 책상이 콘셉트다. 남색 잉크 바탕에 브랜드·행동 색은 앰버 하나만 쓰고, 민트는 정타, 코럴은 오타를 뜻한다.

| 역할 | 글꼴 | 쓰는 곳 |
|---|---|---|
| 숫자·제목 | [Galmuri11 Bold](https://github.com/quiple/galmuri) (OFL, `public/fonts/`에 직접 호스팅) | 로고, 계기판 숫자, 결과 제목, 캔버스 HUD·배너, PvP 방 코드 |
| 한국어 UI | [Pretendard](https://github.com/orioncactus/pretendard) (OFL, jsDelivr) | 버튼·라벨·규칙·순위표 |
| 코드 | JetBrains Mono | 토큰, 입력줄, 콘솔, 키캡 각인 |

- Galmuri11은 12px 격자로 그린 픽셀 글꼴이라 12의 배수(12·24·48·72px)에서 가장 또렷하다. 캔버스 글꼴은 `game-view.js`의 `canvasFont()`로 맞춘다.
- 모드 탭은 실제 키캡처럼 눌린다(고른 모드는 눌려 들어가고 각인이 앰버로 켜짐).
- 계기판은 카드 여섯 개 대신 구분선이 있는 한 줄로 묶었다. 규칙 설명은 '규칙' 접기에 넣었다.
- 휴대폰 던지기 개발자: 팔꿈치를 옆으로 들어 휴대폰을 귀 뒤로 장전 → 몸통·위팔·아래팔 순서로 채찍처럼 휘두름 → 팔이 몸 앞으로 넘어가 가려졌다가 옆으로 내려와 새 휴대폰을 쥐고 올라온다(머리 위를 가로지르지 않음). 휴대폰은 뒤에서 본 손등으로 왼쪽 아래 모서리를 받쳐 쥔다(엄지는 왼쪽 옆면, 네 손가락은 뒷면을 가로질러 오른쪽 옆면을 감음 — 나이키 로고 모양). 손목 관절이 따로 있어 휴대폰은 대체로 서 있고 손목은 ±40° 안에서만 꺾이며, 팔(소매)이 손보다 카메라 쪽에 있어 소맷부리가 손목을 덮는다. 뒷모습은 어깨가 머리 폭의 약 1.44배이고 목 옆에서 약 17° 내려가는 어깨선, 아래로 좁아지는 역사다리꼴 상체(던지는 쪽 어깨는 팔을 들면 올라감), 어깨 폭에 맞춘 의자, 짧은 목, 양쪽 귀, 뒷머리 다발이며 윤곽선 없이 면과 반투명 그늘로만 그린다. 숨쉬기, 실제 키 입력에 맞춰 치는 왼손, 로봇이 다가오면 긴장, 맞으면 움찔, 게임 오버면 서서히 축 처짐.
- 배터리 구조 캐릭터(`battery-characters.js`): 스프링 리그로 숨쉬기·체중 이동·두리번, 조준 중엔 목표를 손끝으로 가리키며 전기(등 뒤 목표면 돌아섬), 한 타마다 까딱, 발사 때 팔 뻗기, 충전·뺏어 오면 점프 환호, 뺏기면 막는 자세, 위급하면 허우적+땀(방전봇은 연기), 화면 꺼짐이면 잠, 끝나면 승리 점프/축 처짐.
- 배터리 구조 화면: 별과 초승달이 뜬 밤하늘, 항공등이 깜빡이고 전파를 내보내는 통신 철탑 스카이라인, 전기가 흐르는 100% 구조선, 원통 음영의 배터리 셀, 탑 빛이 비치고 기포가 오르는 두 겹 바다. 내 탑이 위험하면 바다가 붉게 맥박친다.

### 토큰 소스
| 종류 | 출처 |
|---|---|
| keyword | [highlight.js](https://github.com/highlightjs/highlight.js) 키워드 ∪ [tree-sitter](https://tree-sitter.github.io/) 문법의 키워드 노드, 미사용 예약어·문법 조각은 제외 목록으로 제거 (SQL은 hljs ∩ tree-sitter-sql) |
| operator | tree-sitter `node-types.json`의 기호 노드 (주석·문자열·괄호 구분자 제외) |
| type · builtin · literal | highlight.js |
| 관용구 · decorator · directive | 직접 고른 목록 (`console.log()`, `@Override`, `#include` 등) |

생성 결과는 커밋되어 있어 배포 시 빌드가 필요 없다. 소스나 설정을 바꾸면:
```bash
npm run grammars   # 최초 1회: scripts/grammars에 highlight.js·tree-sitter 문법 설치
npm run tokens     # tokens.generated.js 재생성 + 언어별 출처 리포트 출력
npm test           # 생성 파일이 설정과 일치하는지까지 검사
```

### 랭킹 설계
- **초기화 배치 없음**: 점수는 `lb/{KST ISO 주차}/` 경로에 쌓이고, 주가 바뀌면 새 경로를 읽는다.
- **append-only**: 점수 1건 = Blob 1개. 기존 파일을 고치지 않으므로 동시에 제출해도 기록이 덮어써지지 않는다.
- **세션 서명**: 게임 시작 시 서버가 `{sid, language, duration, startedAt}`에 HMAC 서명한 토큰을 발급. 경과 시간은 서버 시각으로만 판단한다.
- **제출 검증**: 서명 불일치 401 · 형식/시간/속도/점수 상한 위반 422 · 같은 세션 재제출 409. WPM·정확도는 서버가 다시 계산한다.
- **모드별 랭킹**: `lb/`(연습) · `lb-time/`(연습 · 시간 연장) · `lb-throw/` · `lb-battery/`. 아케이드는 생존 시간이 서버가 잰 경과 시간을 넘을 수 없고,
  점수 상한은 각 엔진이 내보내는 글자당 최대 점수(던지기 95, 배터리 35)를 서버가 그대로 import해 쓴다.
- 서버를 못 쓰는 환경에서는 브라우저 로컬 랭킹으로 자동 대체.

### 알려진 한계
- 키 입력 수는 상한만 검증하므로 상한 안쪽의 조작까지 막지는 못한다.
- IP 단위 rate limit이 없다. 필요하면 Vercel Firewall 규칙으로 `/api/*`에 건다.

## 개발
```bash
npm install
npm test            # 엔진·토큰·서버 테스트 (문법 소스 미설치 시 동기화 검사는 skip)
npx vercel dev      # 로컬 실행 (Blob 토큰 필요: vercel env pull)
```
Vercel 프로젝트에 Blob 스토어를 연결하면 `BLOB_READ_WRITE_TOKEN`이 자동 주입된다.
별도 서명 키를 쓰려면 `TYPECODE_SESSION_SECRET`을 설정한다(없으면 Blob 토큰에서 파생).
